# ESUM decision log, full text

Every decision as it was first written: what was decided, what was measured, what was
rejected, and the wording before and after. The rules as they stand now are in
[ARCHITECTURE.md](../ARCHITECTURE.md), whose decision log is a one-row-per-decision index of
this file. A row marked superseded is kept for its history. D-70 was used for two decisions.

|---|---|

| D-2 | Browser modes: managed, attach, and (deferred) sandboxed copy of the saved profile. |
| D-3 | Python. |

| D-12 | Writes gated in code by tier + native Allow/Deny dialog (default and timeout Deny), one dialog per listed batch, JSONL write log. No plan IDs, no firewall in v1. Protects against accidental writes by cooperative agents; not a security boundary against an agent with desktop control or code execution (§9.2). **Superseded by D-34.** |

| D-14 | Login needed → fixed message, user logs in, agent retries; agent never handles credentials. |

| D-18 | No cache between calls: every call fetches live. (A 15-minute disk cache was removed: browser-transport responses answer as the session's logged-in account, which a cache key cannot identify, so one account could be served another's pages.) Instead: identical GETs within one read action are sent once (memory only), and requests to a site are spaced ≥ 0.5 s apart, within and across processes (`extras["min_interval"]`; a site may lower it, see D-87). Retry on 429 for every method, writes included (a 429 means the server did not process the request); reads (GET/HEAD) are retried twice (1 s, 2 s) after 502/503/504, timeouts or dropped connections, writes never (the first attempt may have reached the site); the last error still passes through raw (D-17). State in `~/.esum/`. |

| D-20 | uv packaging; Windows first, cross-platform by design. |
| D-21 | Parallel calls: tab per call in a shared session. |
| D-22 | Engines are code, sites are thin configs, grouped by engine on disk, addressed by site name; custom sites discovered at runtime via `esum list`. |
| D-23 | Separate `esum-site-author` skill; exploration via patchright-cli MCP, observe-only, fresh profile first. |
| D-24 | Integration level decides module vs Markdown site skill; Markdown sites read-only by default, overridable with advisory `esum approve`. **Superseded by D-34.** |
| D-25 | Versioned module format; no trust gate for custom modules in v1. Custom modules are imported lazily, only when their own site is invoked; names come from folder names, never from running code; writes log `custom_code`. (Amended 2026-10-26 after review-r1 #1: eager import let any custom `site.py` swap the gate dialog for built-in writes and `esum approve`.) |
| D-26 | Not LLM judging and not HTTP-method filtering for write detection; any future browser gate uses per-site endpoint rules and fails closed. |
| D-27 | v1 trimmed: chrome-profile mode, per-site limits, live smoke automation and the firewall deferred. |
| D-28 | Refines D-5: a site's transport covers reads; a login-only write may declare its own write transport (engine default, `extras["write_transport"]` override). |
| D-29 | nitan-mcp added as a porting source (Discourse/USCardForum endpoints only, no auth or bypass code); USCardForum is a T3 site because Cloudflare challenges every plain-HTTP request. |
| D-30 | Refines D-5: T2 sends through curl_cffi with Chrome's fingerprint, not httpx (an httpx TLS fingerprint under a Chrome user agent is an easy bot signal). Borrowing the browser's cookies + user agent is the default and per-site optional (`extras["browser_cookies"]`), so T2 also covers fingerprint-checked public sites without a browser. curl_cffi is a required dependency, imported only by T2. |
| D-31 | Supersedes D-29's transport: USCardForum reads go over T2 without browser cookies (Cloudflare challenges httpx but passes curl_cffi's Chrome fingerprint, live-checked 2026-10-26); the bookmark keeps T3 via `extras["write_transport"]`. Requests are spaced per site (not per host), within and across processes. |
| D-32 | Refines D-2: `native` browser mode attaches to the user's everyday Chrome through Chrome's consented remote debugging (live-verified 2026-10-26, Chrome 156). It replaces `chrome-profile`, which App-Bound Encryption defeats on Windows. Opt-in, never default; the skill forbids raw patchright-cli in it. Attach and native use the host context and are detached, never closed. |
| D-33 | Refines D-21: a named patchright-cli tab per call (patchright-cli ≥ 0.8, version-checked; ≥ 0.11 since D-56) replaces tab marks, tab search and the per-step session lock. Parallel calls' browser requests now overlap (live-checked: two FlyerTalk reads in the time of one). Fixes review limitations #4 (lock held during fetch) and #5 (no daemon version contract). |
| D-34 | Supersedes D-12, D-17's second signal and D-24's `esum approve`: no write dialog. Approval is the host agent's permission prompt for the write command; users who allowlist `esum` reads add an "ask" rule for write actions. Tier-only writes, refusal of writes from read actions, and the write log stay. `esum approve` and exit 4 (WRITE NOT APPROVED) are removed; exit 4 is not reused. Trade-off accepted: no approval in bypass/auto-approve hosts, and the prompt shows the command rather than the item and account. |
| D-35 | Two more read-only standalone sites, ported from xgoose: V2EX (public v1 API for topics, replies and nodes; full-history search through the third-party sov2ex index; the token v2 API is not ported, since ESUM never handles credentials) and Substack (any publication's undocumented `/api/v1` archive, post and comment endpoints, read without a login). Both are T1. Remaining xgoose skills are triaged: award searches and Chinese social sites are candidates; X and LinkedIn (replaying observed in-page requests), Amex and Capital One (financial accounts, offer enrollment) and the chat skill (messages sent as the user) are out of scope. |
| D-36 | Supersedes D-34's approval mechanism: approval is the user's request in the conversation, enforced by the skill's rules, not a host permission prompt. ESUM can't stop an agent that goes around it (same OS user), and host rules (Claude Code "ask" rules) bind one host only and are bypassed by `uv run`, `python -m` or a script, so the docs no longer ask users to add them. The trust model is stated: the agent follows the skill; ESUM keeps its own path narrow (one reversible, logged write, no tier 3). No dialog, no exit 4; write log and tier rules unchanged. |
| D-37 | Fixes from the 2026-10-27 architecture review. Untrusted text can't forge the compact format: C0/C1 controls are stripped from every text output in core/output.py (list and search rows included; --json escapes them), user and title are forced to one line (list and search rows wrap every site field in `one_line`), and post-body continuation lines are indented four spaces, so only real post lines start with `[`. Site `extras` keys are declared (`SITE_EXTRAS` in the transport layer, a module `EXTRAS` tuple on engines and optionally on standalone sites); an undeclared key is a registry problem. `site()` / `engine()` take `origin=` for objects built by a helper, and an object created elsewhere that no module registers is a registry problem instead of vanishing. 429 retries cover writes (documented, unchanged). |
| D-38 | `--json` keeps one envelope (`site`, `action`, `untrusted_content`, `data`); the shape of `data` is each action's own, not a cross-site schema. Field names follow similar actions where they fit. The patchright-cli daemon must answer with an explicit `success` flag (a missing one is an error); ESUM follows patchright-cli's published client protocol (docs/daemon-protocol.md there): `patchright-cli daemon-info --json` gives the version, protocol number and token path, read once per install; an unknown protocol is refused up front; the token is read fresh per request (once more after "rejected the auth token"), never printed; installs older than daemon-info fall back to `--version` and the default token path; and its message texts, ESUM's only way to tell a closed tab or session, are matched in one place in `browser/session.py` and pinned by a test. |
| D-39 | Supersedes D-19's "live checks manual": `live/` holds opt-in smoke checks (`uv run pytest live`), outside `testpaths`, so the offline suite never touches the network. Per built-in site: one listing, a thread read from its first row, and one search, all read-only through the real `esum` command with the user's real ~/.esum. They check shape (exit 0, rows with titles, posts numbered from #0/#1 with text), not content. LOGIN NEEDED skips. Each run writes `esum-out/live-report.md` with the date. The 0.9 daemon-token break, invisible to 307 offline tests, is what prompted it. |
| D-40 | Amends D-5 (one transport per site): a site may declare a stronger `fallback` transport, used for the rest of a call after a Cloudflare challenge. Challenge detection (ported from nitan-mcp) moves from the Discourse engine to the transport layer. Challenged writes are resent on the fallback, since a challenge means the request never reached the site. No memory between calls (the user's choice: each call starts on the declared transport). A challenge without a fallback raises a transport-owned error at once instead of three 429 backoffs, including with `check=False`; its short bot-check message and transport-aware `help` follow D-61. uscf and linuxdo are T2→T3. |
| D-41 | Four more read sites, original work (no port): 吾爱破解 `wuaipojie` on a new reusable Discuz! X engine (HTML, GBK; T2 with the browser's cookies, because guests see only page 1 of a thread; no search, which redirects to Bing), 看雪 `kanxue` (standalone, HTML; T2 with cookies so login-only pages are LOGIN NEEDED; "无权访问" stays a raw error; pay-to-view content is labelled, never unlocked), LINUX DO `linuxdo` (a config on the Discourse engine, T2→T3, inheriting the tier-1 bookmark, kept at the user's request) and NodeSeek `nodeseek` (standalone, T2→T3, reads the base64 JSON the pages embed; numbering follows the site, post #0). Site names must start with a letter, hence `wuaipojie` for 52pojie. |
| D-42 | NGA `nga`, a standalone read site ported from xgoose (`nga.xgs.js` 0.1.8): NGA's own JSON pages (`__output=11`) for the forum directory, board and collection lists, title search, hot topics and threads. T2 with the browser's cookies and no fallback (no Cloudflare). Guests can open almost nothing ("访客不能直接访问", whose guest pass is a click on the page that ESUM doesn't make), so the guest and login messages are LOGIN NEEDED and the user logs in in the ESUM browser window. Not ported: profiles, favourite boards and image attachment (personal data, or xgoose-host features). The JSON names authors `UID:<n>`; real names are taken from topic rows and quote headers. |
| D-43 | Adopts AXI (agent experience interface) for the CLI surface. Lists (topics, stories, search hits, boards) return `Listing` and print as TOON tables (the `toon-format` package, TOON spec 4.4) with a small default column set, `--fields` for more, the total count, and a `help` block of complete next commands built from the action's own arguments; an empty list exits 0 with the reason. Threads keep the compact post format (refines D-6). Errors move to stdout as `error:`/`help:` lines, still carrying the raw message (refines D-17); unknown flags name the valid ones. `esum` alone prints a home view (exit 0), and `--version`/`-v`/`-V` print the bare version from a leaf entry module (`esum.entry`) with the package's names loaded lazily. Not adopted: AXI's session hooks (ESUM has no per-session state; the skill is the integration). `limit`, `offset` and `page` are checked before an action runs, with `(max N)` in the argument's doc as the ceiling: a value out of range is a usage error, never quietly changed. |
| D-44 | Refines D-23: `esum-site-author` becomes a step-by-step playbook from a URL to a working site. It ships a read-only probe script (PEP 723, `uv run`; T1/T2 answer, Cloudflare, charset, platform/engine, feeds, embedded data, API paths, raw fixture capture), patchright-cli recipes (a per-site guest session whose profile is deleted before and after; ESUM's managed session, on ESUM's profile and in the agent's own tab, only for logins; never native) and templates. The skill live-runs read actions only: a write action, inherited ones included, runs only when the user asks for that write (D-36). Custom sites keep scrubbed fixtures and tests in their own folder. After a custom site is built, the agent may add, with the user's consent, a trigger skill `esum-<site>` that only routes to `esum docs <site>`, since the `esum` skill's description names built-in sites only. No new CLI command. |
| D-45 | Batch use, from a field report on USCardForum. `--json` output that spills stays one JSON document on stdout (`{"spilled": true, "path": <absolute>}`); text spills also print an absolute, forward-slash path. Two global flags, `--max-retries` and `--min-interval` (or `ESUM_MAX_RETRIES` / `ESUM_MIN_INTERVAL`), let a batch retry HTTP 429 more often, wait up to 300 s, and space its requests further (never closer than the site's own spacing). A 429 records a per-site cool-down beside the D-18 spacing stamp, so every parallel ESUM process waits out the same pause. The Discourse engine gains reads for "everything since a time" and for accounts: `posts --since` (`/posts.json`), `user` (profile + summary) and `user-posts` (`/user_actions.json`, every post, unlike `search --user`); list times are UTC to the minute; `search` takes filters without a query; `latest --no-pinned`. The WordPress engine's `thread --since` uses the same core `parse_since`. A second round (two dogfooding runs) adds: Discourse `thread --since` (one `/posts/by-date` request finds the first post); `ArgumentError` in the public API, so bad arguments (dates, categories, ranges, missing topics or users, search past page 10) exit 2 with a `help:` line; `recent-dps` falling back to the bare keyword; `posts` text rendered as `thread` renders it; a post's time named `date` everywhere; `user` taking several names; `hot`/`top --no-pinned`; member-only categories as LOGIN NEEDED; tier labels saying a write runs only when the user asks (D-36). |
| D-46 | Amends D-14 and D-16 at the user's request: a Discourse site may keep a User API Key, so reads see what the account sees without a browser session (uscf reads over cookieless T2, where a browser login can't help). `login` is interactive and refuses without a terminal, the one deliberate exception to AXI's "no interactive prompts" (D-43), so the user invokes it themselves; they log in and approve in their own browser, and choose the scopes: ESUM sees no password, only a key encrypted to it. The flow is ported from nitan-mcp, plus a nonce check and reuse of the client id so a new login replaces the old key. The key lives in `<ESUM_HOME>/auth/`, is never printed, logged or sent into a page (T3, including after an escalation), and the agent must not read that folder. `logout` (tier 1, a second write action) revokes it. Over cross-origin redirects curl keeps custom headers, so the key trusts the site not to redirect its own API elsewhere. |
| D-47 | Amends D-14: login needed is a notice about one call, not a stop. In a longer task the agent skips what needs a login, finishes the rest and tells the user at the end; the login stays the user's to start, and the agent retries only after that. The exit code (3) and the recognizable `LOGIN NEEDED` message are unchanged. An action over several items (`user --name a,b`) marks an item that needs a login and finishes the others. |
| D-48 | Removes USCardForum's `recent-dps`: deciding what counts as a data point and which words to search is the agent's judgment (D-15), and the preset stayed noisy however it was tuned. `search --recent` does the same with the agent's own words. `run_search`, kept for that preset, folds into `search`. |
| D-49 | What a page says must survive into the output. Code in `<pre>` keeps its whitespace inside a ``` fence, in text and JSON; struck text is `~~marked~~`; images keep their URL, except in `html_to_text` an image the page declares as under 48 px on both sides, a pixel or an icon, which keeps only its alt text. On Kanxue, `thread` reads the Markdown source the page itself sends in a hidden `<textarea>` when the rendered post is cut for guests (`回复或点赞可查看`). This is the user's decision: it reads what the site sends to a guest, without replying, liking or spending points, and it does stand aside from the site's stated condition. A verification page is LOGIN NEEDED, not an empty post. Dates name their zone (NGA UTC, Kanxue UTC+8, vBulletin from the footer). A second round: `Post.likes` may be None when a site doesn't expose it (V2EX), because unknown is not zero; `Post.edited` carries an edit note where a site has one (NodeSeek, vBulletin); V2EX reads 附言 from the topic page, one more request per thread, since the public API leaves them out; sov2ex's reply counts are dropped as unusable, and mixing included and excluded nodes is refused because sov2ex ignores the included ones. A third round: a Discuz post lifted above the thread (推荐, 置顶) names no floor in the page, so it is listed apart rather than given a guessed number, and gaps on page 1 say they may be one of these; a Discuz floor total reads `about` until the last page is read; Substack keeps images, tweets and videos, whose text is only in `data-attrs`, and its archive pages by the rows it got because the API returns fewer than asked. A fourth round: post text must stay unambiguous after any string operation, so a prose line starting with ``` is written ````` and a `<pre>` holding ``` gets a longer fence, as in Markdown; a score a site hides or doesn't give is None, and a negative score stays negative; Reddit keeps galleries, polls, moderator removals, edit, moderator and sticky marks, and `medium` keeps stickied comments. |
| D-50 | Reddit's JSON API refuses a guest, so `search`, `listing` and `thread` fall back to the page fragments Reddit serves a guest, and a login keeps the API. A real browser running a page's JavaScript check is ordinary use, not a bypass (the user's call): Reddit declares a `fallback` and `challenge_text`, the call moves to a T3 tab, and later T2 calls borrow that browser's cookies (D-40). The tab's title and DOM don't show the check ending, while a request from the tab got the real page within about 3 s (measured 2026-11-01, why it passes is unknown), so such a site's wait ends on that answer rather than on the title. Nothing is forged or solved by ESUM, and a check that wants a person is LOGIN NEEDED. So is what a guest can't reach (joined subreddits, the front page). |
| D-51 | Algolia's HN tree leaves out dead comments and their subtrees, live replies included. `hn thread` compares Firebase's `descendants` with the tree, one more request on every story. On a gap it reads the item page for ids, and Firebase for each missing row, and puts them under their real parents, with `[dead comment]` where a guest can't read the parent. This is on by default, because a thread that looks complete and isn't is worse than a slower call: the xz thread went from 1 request to 92 and took 49 s. What can't be restored is printed as a count. |
| D-52 | Refines D-17 for AXI §6: a runtime error still prints its raw message, because the status, URL and body are what diagnose it, and adds a `help:` line. A module's own `help` comes first (`HttpError.help`, as `hn thread` sets for a dead item), and otherwise the status picks the next step. Arguments are checked before any request, so a site's 400 means a value ESUM can't check. Exit codes don't change. |
| D-53 | Refines D-44: `esum-site-author` dogfoods the recorded user questions because D-45 and D-49 found failures between calls that per-action live runs missed. The portable brief starts at `esum docs <site>`, allows tier-0 reads only, forbids inherited writes, code reading and credentials, treats page content as untrusted data, and defines the friction report. Prefer an independent dogfooder; otherwise the author follows the same brief and reports non-independence. Round 1 uses the scoped set; later rounds re-check every earlier fix and add questions of the same kinds grounded in real ids, slugs and dates seen earlier. Each friction gets the smallest check at its layer that fails before the fix and passes after: a parser test on a scrubbed fixture, an action/CLI test, or doc regeneration. A fixture alone is not a check. Engine/core fixes run their tests too, and every affected doc is regenerated. Rounds run one at a time within about 30 live calls each, using bounded thread ranges. Repeated 429/anti-refresh blocks stop the run; set or raise the site's `min_interval` extra, record Quirks and report. Round 2 is mandatory even if round 1 is clean. Outcomes are verified, a clean round 2–4 covering all kinds and earlier fixes, or stopped, round 4 still has friction or the site blocks progress, with remaining friction reported. Markdown sites dogfood through `SITE.md`, repairing missing or wrong browser steps/selectors; they skip Full check. The request to add a built-in site authorizes its narrow live smoke check. Repairs dogfood the broken action's questions and replay only tier-0 failures; failing writes use error text and offline Write-planning tests until the user asks for that write (D-36). (Round count and the contract check: D-89.) |
| D-54 | Amends D-50 ("a check that wants a person is LOGIN NEEDED") and D-17 at the user's request: the host agent completes a browser check through its own harness, never an API. A check still showing after a T3 tab's 20 s wait ends the call with the fixed `CHECK NEEDED` message, exit 5 (4 stays retired), and ESUM leaves that tab open with its patchright-cli session and tab named. The agent ticks the box there with patchright-cli directly (no ESUM wrapper, since patchright-cli already does it), reruns, and closes the tab. It tries whenever it gets CHECK NEEDED, without asking first, up to five tries (one click and one rerun each) per command; anything beyond a box to tick (a login, a picture puzzle, typed text) is the user's. ESUM still solves nothing, calls no solver service and runs no code for the check, so D-5 stands. The call's own request is no longer sent into a tab that still shows the check. A write action the check stops midway names the items already written in its help (set by the write gate), and the agent reads each item's state and reruns only the rest, since a rerun replays the whole command (found in review). Native mode keeps LOGIN NEEDED and closes the tab: that tab is in the user's own Chrome, where the agent runs only `esum`. Rejected: loading a solver extension or calling a solver API (2captcha, NopeCHA, noCaptchaAI). |
| D-55 | Amends D-5 at the user's request: besides the generic fetch, ESUM may run code inside a captcha vendor's own frames (`challenges.cloudflare.com`, `*.hcaptcha.com`, `www.google.com/recaptcha`, `www.recaptcha.net`), and nowhere else: never in a site's page. Such code is a fixed patch shipped in ESUM, reviewed and tested; the agent never writes page code. Still no solver service and no forged page (D-50, D-54). No patch ships yet. The known one (turnstile-bypass's `screenX/screenY` override, for CDP clicks whose `screenX` equals `clientX`) isn't needed here: measured 2026-11-02 on a Turnstile demo in headed patchright Chrome, a mouse click inside the Turnstile frame had `screenX` 330 against `clientX` 29, matching the window position. patchright-cli 0.10 also offers no channel for it (no init script, no Chrome arguments, `eval` reaches the top frame only), so a patch first needs one there. |
| D-56 | Refines D-33 and D-38: ESUM requires patchright-cli ≥ 0.11. Earlier versions send CDP `Runtime.enable` on every page to capture console messages, and a page can detect that (fpscanner's check reports `cdp=true`; iphey.com rated ESUM's T3 tabs "Unreliable"). 0.11 enables it only after a `console` command, which ESUM never sends. `live/test_stealth.py` checks it in ESUM's real session: a `data:` page sets `Error.prepareStackTrace` and logs an Error; a control session with `console` on must trip the same probe. Every supported install has `daemon-info`, so `--version` is read only to name an older install in the upgrade message; the default token path stays for when ESUM can't run patchright-cli but a daemon is listening. |
| D-57 | ESUM requests only web URLs (`http(s)://` with a host), a rule defined once in `core/urls.py`. It is enforced at both ends: `site()` refuses a non-web `base_url` when the module loads (a custom site then reports `error: site '<name>' failed to load`, exit 1, with a `help:` naming the repair, rather than "unknown site" with the usage code: AXI §6, §9), and `HttpClient.url` raises `UnsupportedURL` (exit 1) for any non-web request URL before a transport sees it. A URL is absolute when it names a scheme (`x://`, any case), so `file:///…` is refused, not appended to `base_url`. The transports disagree, which is why ESUM checks itself: curl_cffi (T2) reads a `file://` URL from disk (it refuses one only in a redirect), httpx (T1) refuses it. patchright-cli's per-request `--web-only` would guard only T3's tab navigation. |
| D-58 | Refines D-38: failures are classified by code, decided at one boundary. patchright-cli 0.11.1 puts a stable `code` on failed replies (`session_not_open`, `tab_not_open`, `target_closed`, `no_page`). `reply_code` in `browser/daemon.py` takes that code, else derives one from the daemon's or Playwright's whole message, anchored where the daemon puts it because `eval` passes a page's own exception text through (a daemon before 0.11.1, or one started before an upgrade; and the stale-token rejection, which has no code in any version, as ESUM's own `auth_rejected`). `BrowserError.code` carries it, and `is_closed`, `is_not_open` and `is_tab_gone` read only the code, so message text is read in one place and the shim can go once no supported daemon lacks codes. Codes matter beyond rewording: 0.11.1's reply for a default-tab page that closed outside the daemon is `target_closed` with text that never says "has been closed". The minimum stays 0.11; test fakes speak 0.11.1. |
| D-59 | Refines D-56 at the user's request: the agent keeps patchright-cli at the version ESUM names. On ESUM's too-old error it runs the `help:` line's commands without asking (`uv tool install -U patchright-cli`, then `patchright-cli kill-all`, because a daemon started before the upgrade keeps the old version) and reruns, telling the user at the end. The version lives only in `MIN_VERSION`; the skill names no number, so it can't go stale. |
| D-60 | Deepens thread assembly into `core/thread_view.py`: callers supply exactly the posts to display, inclusive `(first, last, reason)` coverage spans, and an optional actual count. Core owns sorting, deduplication, gap placement, merging, the header count, JSON `posts`, and the spill summary through `thread_view(posts, spans, *, count=None)`. The first covering span supplies a missing number's opaque reason; uncovered numbers default to not read. Reversed spans are ignored and the boundary walk never visits every omitted floor. Small helpers build ordinary read/not-read spans and UTC cutoff labels; sites choose #0, opening context, focused ranges, and the ordering of special reasons such as members-only or unnumbered recommended posts (D-49), without core knowing those site rules. The view's numbering domain and actual count remain separate, so articles, deleted floors and partially loaded comment trees cannot silently change count semantics. Discourse keeps its fetching, megatopics and API-key logic; engines keep site-specific notes and appendices. All built-in thread actions use this view; FORMAT 1's public `with_gaps` and `render_thread` remain compatible.
